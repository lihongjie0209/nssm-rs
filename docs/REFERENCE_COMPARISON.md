# NSSM reference comparison

This report records direct black-box checks against the pinned NSSM release.
It is a partial report, not the command-by-command release acceptance report.

## Reference and environment

- Source: `ONLYOFFICE/nssm` commit `f28f043161cf6d21c2bf5f923c23b1fbe74d236d`
  (tag `v2.24.1`).
- Reference executable: `nssm_x64.zip` from the
  [v2.24.1 GitHub release](https://github.com/ONLYOFFICE/nssm/releases/tag/v2.24.1).
- Downloaded archive SHA-256: `dd15b0bd3541f954220b8c0622a40294b919dfd0e6635859e733f153ba34bceb`.
- Earlier direct comparisons ran both binaries on the same local Windows host;
  the repeatable paired workflows run both binaries on the same GitHub
  `windows-latest` runner.
- Output comparisons normalize trailing whitespace and, for service lists,
  sort service names before comparing.

The repeatable Windows reference sweep is available as the manually triggered
`Reference compatibility` GitHub Actions workflow. It downloads the pinned
archive, checks the SHA-256 above, builds nssm-rs, and runs only the recognized
read-only cases in `tests/reference_readonly_sweep.ps1`. It deliberately avoids
no-argument NSSM invocation (which may display its GUI dialog) and commands that
can request UAC elevation. The sweep runs separately from CI so the ordinary
build and service integration jobs remain network-independent.

## Checks completed

| Scenario | Result |
|---|---|
| Usage and help | The reference sends unrecognized commands, including `help`, to `usage()`. With no attached console/output handle, upstream calls its GUI usage dialog; that path is excluded from automated reference scans. nssm-rs intentionally provides CLI-only `help`, `-h` and `--help`, and prints no-argument usage to stderr with status 1. |
| `list all ignored` | Both exited 0 and returned the same 331 service names. This confirms the reference behavior of considering only the first optional argument. |
| `list definitely-not-all` | Both exited 0. The host had no NSSM-managed services, so both returned no names. |
| `list` and `list all` | Rechecked both commands against the pinned executable on 2026-10-15; output and exit status matched on this host. |
| Read-only command sweep | The [2026-10-15 Windows reference workflow](https://github.com/lihongjie0209/nssm-rs/actions/runs/38805825337) matched all 107 then-configured cases against pinned NSSM v2.24.1. On 2026-10-16, the local sweep removed missing-service `remove confirm` because NSSM requests UAC before service lookup, and fixed process-exit capture so version switches validate actual exit code 0. The resulting 106 safe cases all matched locally against the hash-verified pinned executable. Nine version switch forms check successful exit, nonempty stdout, and empty stderr rather than byte equality. Coverage includes native SCM metadata (`Name`, `ImagePath`, `DisplayName`, `ObjectName`, `Description`, `Environment`, `Start`, `Type`, and dependencies) on Spooler and Schedule, all 39 managed-setting queries against the native Spooler service, missing-service operations for get/set/reset/unset and every SCM control command, missing `AppExit`/`AppEvents` subparameter precedence, a non-elevating `dump` with a target name, single and multiple-service process reporting, display-name lookup, and status/statuscode. The sweep skips NSSM invocations that can display a GUI dialog and commands that can request elevation. |
| Disposable service lifecycle comparison | The [2026-10-15 Windows reference workflow](https://github.com/lihongjie0209/nssm-rs/actions/runs/38805455904) matched 289 install/configure/query/start/status/stop/remove operations against NSSM v2.24.1 and nssm-rs using the same temporary service name and `PING.EXE -t 127.0.0.1`. It includes all 28 managed DWORD settings, AppParameters, AppDirectory, all three stream paths, AppAffinity, AppExit, AppEvents, AppEnvironment, AppEnvironmentExtra, Description, DisplayName, ObjectName, Start, Type, ImagePath, DependOnGroup, DependOnService and service Environment, as well as restart, pause, continue, rotate, a complete configured-service dump and native setting output order. Exit codes and redirected stdout/stderr bytes matched for every operation, including rejected invalid DWORD/priority/affinity updates with stored-value preservation, Name write rejection, ImagePath update and restore, native dependency reset behavior, reset of Start/Type without defaults and confirmed removal. Upstream resets for AppParameters and AppDirectory are excluded because pinned NSSM crashes on them; nssm-rs reset behavior remains covered by its Windows integration suite. |
| Managed-setting rejection on native services | Querying all 39 managed setting names against Spooler found two compatibility issues: errors needed NSSM's extra carriage return, and `AppExit`/`AppEvents` without a subparameter must report that missing argument before rejecting a native service. nssm-rs now matches those bytes and error precedence; Windows process tests assert the exact stderr bytes for all three cases. |
| Explicit empty string setting | The paired reference workflow confirmed that `set AppDirectory ""` is a successful set operation in NSSM. nssm-rs now reports it as set, preserving empty string values distinctly from `reset`; unit and Windows SCM integration tests cover the behavior. |
| `reset Start` and `reset Type` | Both exit with code 6 and produce identical NSSM diagnostics because neither has a meaningful reset default. The lifecycle comparison verifies the raw stderr bytes. |
| `reset DependOnService` and `reset DependOnGroup` | Paired lifecycle tests show `reset DependOnService` clears service dependencies, while `reset DependOnGroup` succeeds but leaves group dependencies unchanged. The Windows SCM test verifies both behaviors and confirms the service reset preserves group dependencies. |
| Rejected setting updates | Invalid AppNoConsole, AppPriority, AppRotateBytes and AppAffinity values all exit 6 with matching reference diagnostics; readback verifies each failed update preserves the prior value. Priority and affinity diagnostics include their reference validation details. |
| Native `ImagePath` update and `Name` write rejection | Paired lifecycle tests verify that setting `ImagePath` to its current value succeeds without changing it, while `set Name` fails. This corrects the original inventory assumption that both settings are query-only. |
| `status Spooler` and `statuscode Spooler` | Output and status matched exactly. Both statuscode invocations returned the host's `SERVICE_RUNNING` numeric code (4). |
| `processes Spooler` when the service process cannot be opened | Both exited 0 and emitted no process-tree stdout. Direct local `Start-Process` redirection confirmed exact stderr bytes, including the localized system error and NSSM's trailing blank line. nssm-rs now formats this path with the Windows system message instead of Rust's `(os error N)` suffix; a Windows unit test checks the message shape and line endings. |
| `dump` for equivalent installed services | The 289-operation paired lifecycle run compared complete output after normalizing the executable path and service name. It verifies install/configuration lines, Windows shell escaping, all configured settings in reference order, duplicate AppExit default lines, dependencies, Description, DisplayName, ObjectName, Start and Type. The pinned NSSM dump iterates every AppExit registry value but reads and emits the default action for each one; code-specific actions are therefore omitted and the default line may repeat. nssm-rs reproduces this upstream behavior. |
| `dump` for a native SCM service | A Windows integration test creates a disposable service directly through SCM and verifies the dump emits its install command plus native Start and Type settings, without requiring an NSSM `Parameters` registry key. |
| `dump Schedule` when the caller lacks change-config access | The pinned reference requires `SERVICE_CHANGE_CONFIG` even though dump reads configuration. NSSM requests UAC elevation for this case; nssm-rs intentionally avoids GUI prompts and reports that the caller must rerun from an elevated terminal. This scenario is excluded from the non-interactive reference sweep because the reference can display a Windows consent dialog. |
| Managed/native setting set/get sweep | Set and read back AppNoConsole, AppPriority, AppRestartDelay, AppThrottle, AppRotateBytes, AppAffinity, AppExit Default, AppEnvironmentExtra, AppParameters, AppDirectory, Description, DisplayName, ObjectName, Start and Type on paired temporary services. Exit codes and normalized output matched for every case. |
| String and hook setting set/get/reset sweep | AppParameters, AppDirectory, AppStdin, AppStdout, AppStderr, AppAffinity, AppEnvironment, AppEnvironmentExtra, AppExit and AppEvents matched in values and reset defaults. On this host, resetting AppParameters or AppDirectory with the pinned NSSM binary terminated it with Windows status `0xC0000374` (heap corruption); nssm-rs completes the same reset successfully. This reference crash is recorded as an intentional safety difference. |
| `get Spooler Start` | Both exited 0 and returned the same startup type. |
| `get Spooler Type` | Both exited 0 and returned the same service type. |
| `get Schedule Type` | The pinned NSSM returns `SERVICE_WIN32_SHARE_PROCESS`; nssm-rs initially returned `SERVICE_TYPE_32`. Native type formatting now matches all six NSSM service-type names, with unit coverage and a Windows SCM assertion for a shared-process service. |
| Native service lookup by display name | `get "Task Scheduler" Start` and `get "Task Scheduler" Name` match the pinned reference byte-for-byte on the local Windows host. The integration test verifies display-name resolution and that `Name` returns the canonical key `Schedule`. |
| `get Spooler DisplayName` | Both exited 0 and returned the same display name. |
| `get Spooler ObjectName` | Both exited 0 and returned the same account name. |
| `get Schedule AppRotateBytes` | Both exited 1 with empty stdout and the same diagnostic: `Parameter "AppRotateBytes" is only valid for services managed by NSSM!`. nssm-rs now identifies native services before looking up managed settings; a Windows integration regression test covers this path. |
| `get Spooler DependOnService` | Both returned `RPCSS` and `http` in the same order. The reference emits `CR CR LF` between items and CRLF at the end; nssm-rs now reproduces those exact line-ending bytes for all CLI multi-string reads. |
| `set/get AppAffinity` | Directly compared on the same Windows host: `0-1` reads back as `0,1`; `0,1,2` reads back as `0-2`; `Default`, `All`, and `*` each read back as `All`. nssm-rs matches the reference output and exit status for these values. |
| `set/get AppAffinity 0-64` | Both binaries accept this range and read it back as `0-63` on the pinned x64 reference build. The reference parser checks the range start but not its end; nssm-rs reproduces the observed x64 result with explicit wrapping mask logic. A standalone CPU index `64` is rejected by both; both return exit code 6 and preserve the prior setting. |
| `get <new-service> AppExit Default` immediately after install / after first start | Both return `Restart`. NSSM creates the `AppExit` default during install; nssm-rs now does the same. A missing default inside an existing malformed key remains handled deterministically as `Restart` rather than NSSM's uninitialized control character. |
| `get Spooler Description` | Direct `cmd.exe` file redirection showed identical raw bytes, including `?` replacement and CRLF. In PowerShell's native-command pipeline, both emit the same localized text. The reference selects UTF-8 when launched from an existing console; nssm-rs now mirrors that mode, writes UTF-16 to console handles, and uses the MSVC CRT's code-page-1252 no-best-fit conversion when launched without an existing console. A Windows lifecycle integration assertion checks redirected bytes. |
| `statuscode` for a missing service | Both exited 0, matching NSSM's documented failure sentinel. On the local Chinese Windows host, raw stdout and stderr bytes now match exactly, including NSSM's localized system error replacement and CRT line endings. |
| SCM status during startup and runtime | NSSM reports no accepted controls in its initial `SERVICE_START_PENDING` state, then accepts stop, shutdown, and power controls during application startup; its reported service type includes `SERVICE_INTERACTIVE_PROCESS`. nssm-rs now matches those status fields. Unit coverage checks startup control masks, and the Windows smoke test verifies the running service's real control mask and service type. |
| Missing-service lookup for `status`, `start`, `stop`, `restart`, `pause`, `continue`, `rotate`, `get`, `set`, `reset`, and `statuscode` | Directly compared on the local Windows host: exit status and raw stdout/stderr bytes match for each command, including the NSSM message resource line endings and localized system error. The Windows integration test covers the status and statuscode message shape. |
| Unknown setting on a missing service | Direct reference comparisons for `get`, `set`, and `reset` showed that invalid-setting diagnostics take precedence over the missing-service lookup error. nssm-rs now follows that order; a Windows CLI integration test checks all three commands, exit status, and diagnostic class. |
| Missing-service `remove` | NSSM checks administrator status and requests elevation before looking up the service. nssm-rs deliberately does not request UAC elevation because it is command-line-only; it prints an administrator-required diagnostic and exits without opening a dialog. |
| `processes` for missing and multiple services | Both return exit code 1 and emit the same raw stderr bytes on the local Windows host. A two-service comparison confirms that the missing-service `EnumServicesStatus()` diagnostic precedes the following service's process-open diagnostic, as it does in the reference. The Windows integration regression covers missing-service exit code and diagnostic shape. |
| Service manager open failure | NSSM logs event 1002 for an administrator when `OpenSCManager()` fails. nssm-rs now preserves the OS error and emits the corresponding Application event; a Windows unit test forces the API failure with an invalid access mask and checks the event when already running as administrator. |
| Forced application termination | NSSM terminates the child with exit code 0 when the service stop methods reach `Terminate`. nssm-rs now passes 0 to both `TerminateProcess` and `TerminateJobObject`; the Windows service integration configures an `Exit/Post` hook and asserts it receives `NSSM_EXITCODE=0` after a forced stop. |
| Process-tree termination events | NSSM records event 1023 for each process and event 1027 for each successfully opened process in a managed service tree. nssm-rs now enumerates the process tree before job termination and emits those records; the descendant-stop integration test checks both events for the two child PIDs. |
| Invalid configured priority | Upstream `registry.cpp` checks `AppPriority` against `priority_mask()`, logs informational event 1066 when unrelated bits are present, and starts with normal priority. nssm-rs now follows that mask and fallback; a Windows service integration scenario writes an invalid DWORD directly to the isolated service key, verifies event 1066 insertion values, and confirms the child runs with priority class 32 (`NORMAL_PRIORITY_CLASS`). |
| Invalid configured affinity | Upstream `registry.cpp` logs warning event 1067 with the service name and requested affinity string when it cannot parse the registry value, then permits the application to use any CPU. nssm-rs now logs the same event and ignores the invalid mask; the Windows service integration test writes a malformed string directly to the isolated service key and checks the event fields. |
| Invalid millisecond registry value types | Upstream `registry.cpp` falls back to each setting's default and logs its specific warning for non-DWORD values. nssm-rs now follows this for `AppThrottle`, `AppRestartDelay`, `AppRotateDelay`, and the three stop grace periods. The Windows SCM integration writes invalid string values for `AppThrottle`, `AppRestartDelay`, and `AppStopMethodConsole`, then verifies fallback values and events 1036, 1071, and 1056 in [CI run 38781087477](https://github.com/lihongjie0209/nssm-rs/actions/runs/38781087477). |

| Requested affinity exceeds the process group | Upstream `registry.cpp` intersects the requested `AppAffinity` mask with the service process's supported mask and logs warning event 1068 with the requested, supported and effective processor lists. nssm-rs now reports the same four insertion values and constrains the child process to the intersection; the Windows integration scenario adds an unavailable processor bit and checks both the event and the child's actual affinity. |
| Affinity API failures | Upstream `service.cpp` logs warning 1069 when `GetProcessAffinityMask()` fails and error 1070 when `SetProcessAffinityMask()` fails. nssm-rs now creates affinity-constrained children suspended, applies the requested priority and effective affinity before resuming the child, and reports those API failures; a Windows unit test passes an invalid process handle through the production API path and verifies both events. |
| Invalid stop-method registry type | Upstream `registry.cpp` logs warning event 1052 with service, setting name and `NSSM` when `AppStopMethodSkip` cannot be read as a DWORD, then enables every stop method. nssm-rs now reads this setting during service startup, follows the same fallback, and reports the event; the Windows service integration test writes a string value to the isolated service key and checks all three event insertions. |

| SCM recovery flag | Upstream `service.cpp` enables `SERVICE_FAILURE_ACTIONS_FLAG.fFailureActionsOnNonCrashFailures` during installation and service startup. nssm-rs now applies the flag at both points; the Windows SCM lifecycle integration queries `SERVICE_CONFIG_FAILURE_ACTIONS_FLAG` after install and verifies the flag is enabled. |

| Start/Pre hook abort | Upstream `service.cpp` logs error event 1079 with `START`, `PRE`, service name and exit code 99 when the hook requests startup abort. nssm-rs now emits the same record; the Windows SCM integration verifies its four insertion values and confirms the application did not start. |

## Remaining comparison work

Run successful and failing black-box scenarios for every supported command,
setting, and relevant argument form. Compare output text and bytes, process exit
codes, service configuration, registry effects, event log records, and child
process behavior. Record each case here and resolve or explicitly document every
remaining difference before release acceptance.

The latest recorded GitHub CI run on commit `0264806` passed the complete Windows
SCM integration job and the Linux suite. The separate reference workflow failed
before running the candidate's failed-restart scenario: it stopped while running
the pinned NSSM binary and reported that event 1007 was missing, with the service
already stopped. The failure message now includes the tested binary, all missing
event IDs, and the observed event properties so the next privileged Windows run
can identify whether this is a reference scenario assumption or a real parity
difference. The local working tree has not yet been revalidated by GitHub Actions.
